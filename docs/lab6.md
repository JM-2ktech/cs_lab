# Lab 6. 도구를 만들고, 도구를 데려온다 🧩

> **이번 랩 완성물**: 조회 조건과 실행 순서를 내가 정한 **에이전트 흐름** 하나. 그리고 밖에서 가져온 **MCP 도구** 하나
> **예상 시간**: 50분 · **완성 신호**: [Lab 5](./lab5.html) 23번과 **똑같은 요청**을 던졌는데 값이 제자리에 들어간다

{: .time }
50분 타이머. 5단(흐름 만들기 → 읽는 조건 → 쓰는 자리와 순서 → 같은 요청 다시 → 도구 데려오기)으로 나눠 진행합니다.

- **[Lab 5](./lab5.html)까지 마친 에이전트**와 **본인 OneDrive의 `정산_기준표.xlsx`** 를 그대로 씁니다.
- [Lab 5](./lab5.html) 25번에서 적은 세 문장을 꺼내 두세요. 이 랩은 그 셋을 하나씩 해결합니다.

## 개념 (5분)

{: .time }
이 5분은 아래 「예상 시간 50분」에 포함되지 않습니다.

[Lab 5](./lab5.html)에서 커넥터가 못 한 것이 세 가지였습니다.

| | [Lab 5](./lab5.html)에서 | 흐름에서는 |
|---|---|---|
| **읽는 조건** | 표를 통째로 가져왔다 (11번) | 몇 개를, 어떤 조건으로 읽을지 내가 적는다 |
| **쓰는 자리** | 값이 엉뚱한 칸에 들어갔고 성공으로 보고됐다 (22·24번) | 칸마다 무엇을 넣을지 내가 잇는다 |
| **쓰는 범위** | 다섯 건이 한꺼번에 들어갔다 (23번) | 입력이 한 건이라 한 건씩 나눠 쓴다 |

{: .important }
**흐름은 도구를 만드는 도구입니다.** 지금까지 붙인 커넥터는 만들어져 있는 것을 가져다 쓴 것이고, 흐름은 여러 동작을 묶어 새 도구 하나로 만드는 자리입니다. 오케스트레이터에게는 둘 다 그냥 도구 하나로 보입니다.

한 가지가 더 따라옵니다. **흐름은 적힌 것만 합니다.** 도구를 붙여 두면 오케스트레이터가 그 도구로 할 수 있는 일을 전부 시도할 수 있지만, 흐름은 그 안에 그려진 절차 밖으로 나가지 못합니다. 이것이 [Lab 5](./lab5.html) 23번의 답입니다.

| | 대화 | 실행 |
|---|---|---|
| 내가 정하는 것 | [Lab 4](./lab4.html) 토픽 | **Lab 6 흐름** |
| 맡기는 것 | 생성형 오케스트레이션 | 커넥터 직접 호출 |

## 단계 — ① 흐름을 만든다 (16분)

1. **도구 → 도구 추가**를 엽니다. [Lab 5](./lab5.html) 6번에서 아래쪽 탭만 썼는데, 이번에는 위쪽 **새로 만들기**에서 **에이전트 흐름**을 고릅니다.

    ![도구 추가 — 새로 만들기 · 에이전트 흐름](../assets/lab6/lab6-01.png)

    {: .note }
    같은 화면입니다. **가져다 쓰는 자리와 만드는 자리가 나란히** 있습니다.

2. 흐름 편집기가 열립니다. **이름부터 바꾸려 하면 저장되지 않습니다.** 툴바의 **초안 저장**을 먼저 누르고, 그다음 좌측 상단 이름을 바꿉니다.

    ```
    정산 신청 처리
    ```

    **완료 기준**: 이름이 「제목 없음」에서 바뀌고, 다시 저장된다.

    ![초안 저장 먼저, 그다음 이름](../assets/lab6/lab6-02.png)

    {: .note }
    저장 버튼이 **초안 저장**이고 그 옆이 **게시**입니다. 둘은 다릅니다 — 초안은 나만 볼 수 있고, 에이전트가 부르려면 게시해야 합니다. 9번에서 게시합니다.

    {: .note }
    툴바에 **흐름 검사기**와 **테스트**가 있습니다. 10번에서 테스트를 씁니다.

3. **트리거** 노드를 봅니다. 방금 저장한 직후에는 이름이 `manual` 처럼 영문으로 보일 수 있습니다. **다른 화면에 갔다가 되돌아오면** 제 이름으로 표시됩니다.

    **완료 기준**: 트리거가 **「에이전트가 흐름을 호출할 때」**이고, 그 아래에 **「Respond to the agent」** 노드가 이미 놓여 있다.

    ![트리거와 응답 노드 — 처음부터 두 개가 있다](../assets/lab6/lab6-03.png)

    {: .important }
    **이 흐름은 사람이 시작하지 않습니다.** 일정이나 버튼이 아니라 에이전트가 부를 때만 돕니다. 그래서 트리거를 고를 일이 없습니다.

    {: .note }
    **응답 노드도 처음부터 있습니다.** 흐름이 무엇을 하든 에이전트에게 돌려주는 것으로 끝난다는 뜻입니다. 우리는 그 사이를 채웁니다.

4. 트리거 노드를 눌러 속성을 엽니다. **매개 변수** 탭의 **입력 추가**를 누릅니다.

    ![트리거 속성 — 입력 추가](../assets/lab6/lab6-04.png)

    형식을 **텍스트**로 두고 이름을 아래로 씁니다.

    ```
    구간코드
    ```

    ![입력 하나 — 텍스트 · 구간코드](../assets/lab6/lab6-04b.png)

    {: .note }
    아래 **익스프레스 모드(프리뷰)** 는 건드리지 않습니다. 실행을 빠르게 하는 설정인데 프리뷰 단계입니다.

5. **입력 추가**를 한 번 더 눌러, 이번에는 형식을 **숫자**로 지정합니다.

    ```
    수량
    ```

    **완료 기준**: 입력이 두 개 있고 형식 아이콘이 서로 다르다.

    ![입력 두 개 — 텍스트와 숫자](../assets/lab6/lab6-05.png)

    {: .important }
    **여기가 [Lab 4](./lab4.html) 25번과 같은 자리입니다.** 토픽에서 변수를 입력으로 열었던 것처럼, 흐름도 밖에서 받을 값을 미리 정해 둡니다. 다만 흐름은 **형식까지** 정합니다 — `수량`에 글자를 넣으면 실행 전에 막힙니다.

    {: .note }
    [Lab 5](./lab5.html) 23번에서는 다섯 건이 한 번에 들어갔습니다. **이 흐름은 구간코드 하나와 수량 하나만 받습니다.** 여러 건을 넣을 자리가 처음부터 없습니다.

6. 트리거 아래 **+** 에서 **Excel Online (Business)** 를 고르고, 작업 목록에서 **테이블에 있는 행 나열**을 넣습니다.

    ![작업 추가](../assets/lab6/lab6-06.png)

    ![Excel 작업 목록 — 흐름 안에서는 더 넓다](../assets/lab6/lab6-06b.png)

    {: .important }
    [Lab 5](./lab5.html) 6번에서 본 목록보다 넓습니다. 「행 삭제」·「행 업데이트」·「테이블 만들기」까지 있습니다. [Lab 5](./lab5.html) 23번에서 상태를 못 바꿨던 그 도구가 여기에는 있고, 우리는 쓰지 않습니다. **무엇을 안 붙일지도 설계입니다.**

7. 매개 변수를 채웁니다. 위치·문서 라이브러리·파일을 본인 것으로 고르고, 테이블은 **`단가표`** 로 지정합니다. 민감도 레이블 두 칸은 비워 둡니다.

    **완료 기준**: 파일 칸에 `/문서/정산_기준표.xlsx` 처럼 **경로가 보인다.**

    ![흐름 안 Excel 액션의 매개 변수](../assets/lab6/lab6-07.png)

    {: .important }
    **[Lab 5](./lab5.html) 9번에서 `Table` 칸이 긴 코드였던 것을 떠올립니다.** 여기서는 파일도 테이블도 **사람이 읽을 수 있는 이름**으로 보입니다. 무엇을 가리키는지 눈으로 확인할 수 있습니다.

    {: .note }
    칸마다 **「AI로 동적으로 채우기」 선택지가 없습니다.** 흐름 안에서는 값을 내가 넣거나 앞 노드에서 받아옵니다.

8. 3번에서 본 **Respond to the agent** 노드를 엽니다. 출력 이름을 `결과` 로 두고, 값에 Excel 액션의 **`body/value`** 를 끼웁니다.

    **완료 기준**: 출력이 하나 있고 값이 앞 노드에 연결되어 있다.

    ![응답 노드 — 결과에 body/value 연결](../assets/lab6/lab6-08.png)

    {: .note }
    출력에도 **설명**을 붙일 수 있습니다. 오케스트레이터가 이 흐름의 결과를 어떻게 읽을지에 쓰이는 자리인데, 오늘은 비워 둡니다.

9. **초안 저장** 후 **게시**합니다. **완료 기준**: 게시 완료 표시가 뜬다.

    ![흐름 저장·게시](../assets/lab6/lab6-09.png)

    {: .warning }
    흐름도 게시해야 에이전트가 부를 수 있습니다. 고칠 때마다 다시 게시합니다.

10. 툴바의 **테스트**를 누릅니다.

    ![툴바의 테스트](../assets/lab6/lab6-10.png)

    **흐름 테스트**에서 **수동**을 고르고 **게시 및 테스트**를 누릅니다.

    ![흐름 테스트 — 수동](../assets/lab6/lab6-10b.png)

    {: .note }
    **자동**은 지난 실행을 다시 쓰는 방식인데, 처음이라 「이 흐름의 실행이 없습니다」로 막혀 있습니다.

    {: .note }
    버튼이 **게시 및 테스트**입니다. 9번에서 게시했더라도 테스트할 때 한 번 더 게시합니다. **고친 것이 반영되지 않았다면 여기부터 다시 눌러 봅니다.**

    **흐름 실행** 패널에 값을 넣고 **흐름 실행**을 누릅니다.

    ```
    구간코드   TR-03
    수량       4
    ```

    ![흐름 실행 — 입력값](../assets/lab6/lab6-10c.png)

    {: .note }
    4·5번에서 만든 입력이 그대로 칸이 됐습니다. **형식도 따라옵니다** — `수량` 칸에는 숫자만 들어갑니다.

11. 실행하면 **활동** 탭으로 넘어갑니다. **완료 기준**: 노드 세 개에 소요시간과 체크가 붙는다.

    ![활동 탭 — 노드별 실행 결과](../assets/lab6/lab6-10d.png)

    {: .note }
    [Lab 4](./lab4.html)·[Lab 5](./lab5.html)의 **계약 테스트 창**과 같은 그림입니다. 거기는 에이전트 쪽에서 본 것이고 여기는 흐름 쪽에서 본 것입니다.

    **테이블에 있는 행 나열** 노드를 눌러 **출력**을 봅니다. `statusCode` 가 `200` 이면 호출은 성공입니다. 그 아래 **원시 출력 표시**를 누릅니다.

    ![출력 패널 — 원시 출력 표시](../assets/lab6/lab6-10e.png)

    **완료 기준**: `body` 의 `value` 에 **다섯 행이 전부** 들어 있다.

    ![원시 출력 — 다섯 행이 전부 들어 있다](../assets/lab6/lab6-10f.png)

    {: .important }
    **아직 [Lab 5](./lab5.html)와 똑같습니다.** 흐름으로 감쌌을 뿐 읽어 오는 양은 그대로입니다. `TR-03` 하나를 물었는데 `TR-01`부터 `TR-05`까지 다 왔습니다. 조건을 거는 것은 다음 절에서 합니다.

    {: .note }
    `@odata.etag` 나 `ItemInternalId` 처럼 우리가 넣지 않은 값도 같이 옵니다. **읽어 오는 것은 표의 내용만이 아닙니다.**

12. 6번의 Excel 액션을 열고 **고급 매개 변수** 드롭다운을 펼칩니다. 여섯 개가 체크박스로 들어 있습니다.

19. 금액을 담을 변수를 만듭니다. **조건 노드보다 위**에 **변수 초기화**를 넣습니다. 이름 `금액`, 유형 **정수**, 값 `0`.

    ![변수 초기화 — 금액 / 정수](../assets/lab6/lab6-19.png)

    {: .warning }
    **변수 초기화는 갈래 안에 넣을 수 없습니다.** True 갈래에 놓으면 저장이나 게시에서 막힙니다. 조건보다 위, 갈래가 갈라지기 전에 놓아야 합니다.

    {: .important }
    **[Lab 4](./lab4.html) 28번과 같은 얘기입니다.** 거기서도 변수를 갈래 앞에서 만들었습니다. 다른 점은 강도입니다 — 토픽에서는 갈래 안에 만들 수 있지만 값이 밖에서 안 보였고, 흐름에서는 아예 막습니다.

    이제 **True** 갈래에 **변수 설정**을 넣어 값을 채웁니다. 변수는 `금액`, 값에는 아래 수식을 **붙여넣습니다.**

    ```
    mul(int(first(outputs('테이블에_있는_행_나열')?['body/value'])?['단가']), triggerBody()?['number'])
    ```

    **완료 기준**: 조건 위에 초기화가, True 갈래에 설정이 하나씩 있다.

    ![변수 설정 노드 추가](../assets/lab6/lab6-19b.png)

    ![변수 설정 — 이름은 목록에서 고른다](../assets/lab6/lab6-19c.png)

    {: .note }
    **변수 설정에서는 이름을 드롭다운으로 고릅니다.** 앞에서 초기화한 것만 목록에 뜹니다. 여기서 이름이 안 보이면 초기화가 갈래 안에 들어가 있는 것입니다.

    {: .warning }
    **수량을 `triggerBody()?['number']` 로 부릅니다.** 입력 이름(`수량`)이 아니라 **형식 이름**입니다. 입력이 여러 개면 `number_1`·`text_1` 처럼 번호가 붙으므로, 수식을 붙여넣은 뒤 값이 맞는지 한 번 실행해 확인합니다.

    {: .note }
    **수식이 세 겹입니다.** 안쪽부터 읽으면 `first` 로 배열의 첫 행을 꺼내고, `?['단가']` 로 그 행의 단가 칸을 집고, `int` 로 숫자로 바꾸고, `mul` 로 수량과 곱합니다. 붙여넣고 넘어가도 되지만, 어느 조각이 무엇인지는 한 번 짚어 두면 고칠 때 편합니다.

    {: .note }
    수식을 여기 두지 않고 21번의 `금액` 칸에 직접 넣을 수도 있습니다. 그러면 노드는 하나 줄지만 **계산한 자리가 화면에서 사라집니다.** [Lab 5](./lab5.html) 15번에서 없어서 아쉬웠던 것이 바로 그 자리입니다.

    {: .important }
    **16번에서 `length` 를 쓴 이유가 여기서 다시 나옵니다.** 앞 노드가 배열이라 `first` 로 한 행을 꺼내야 합니다. 최대 개수를 `1` 로 둔 덕에 **「첫 행」이 곧 「그 행」**입니다.

    {: .important }
    **[Lab 5](./lab5.html) 15번에서 화면에 없던 그 계산입니다.** 거기서는 모델이 문장 안에서 곱했고 기록이 남지 않았습니다. 여기서는 **노드로 남습니다.**

### 참고 — 실무에서는 흐름을 더 잘게 쪼갭니다

{: .note }
읽고 넘어가는 대목입니다. 만들지 않습니다.

오늘 만든 흐름은 **조회 · 계산 · 기록**을 한 덩어리로 합니다. 배우기에는 이 편이 낫지만, 실제로 쓸 것이라면 보통 더 나눕니다.

| 흐름 | 하는 일 | 왜 나누나 |
|---|---|---|
| 조회 | 구간코드로 단가를 찾아 돌려준다 | 바깥을 바꾸지 않는다. 몇 번 불려도 안전하다 |
| 등록 | 확정된 값을 신청내역에 기록한다 | 바깥을 바꾼다. 언제 불릴지가 중요하다 |
| 변경 | 신청번호 하나의 상태를 바꾼다 | 되돌리기가 가장 어렵다. 따로 두고 따로 관리한다 |

{: .important }
**나누는 기준은 「바깥이 바뀌는가」입니다.** 조회는 몇 번 불려도 그만이지만, 등록과 변경은 한 번 더 불리면 한 줄이 더 생깁니다. 셋을 한 흐름에 두면 **조회만 하고 싶을 때도 쓰기 권한이 딸려 옵니다.**

{: .note }
변경 흐름을 만든다면 입력은 **신청번호 하나**입니다. 「조건에 맞는 것 전부」가 아니라 「이것 하나」로 받으면, 잘못 불려도 한 줄만 바뀝니다. 26~28번에서 본 것과 같은 생각입니다.

## 부록 — 에이전트가 에이전트를 부른다

{: .time }
약 25분. **랩 진행에 필요하지 않습니다.** 시간이 남거나 나중에 혼자 해볼 몫입니다.

[Lab 2](./lab2.html)에서 만든 복리후생 에이전트를 **도구처럼 호출**하는 상위 에이전트를 만듭니다. 지금까지 붙인 커넥터·흐름·MCP 자리에 **에이전트**가 들어갑니다.

지금까지는 에이전트 **하나**에 지식·지침·토픽·커넥터를 계속 얹어왔습니다. 이 방식은 어느 지점에서 무너집니다.

| | 하나에 다 넣기 | 나눠서 부르기 |
|---|---|---|
| 지식이 늘어나면 | 엉뚱한 문서를 근거로 답하기 시작 | 담당 에이전트 안에서만 검색 |
| 지침이 늘어나면 | 규칙끼리 충돌, 매 요청 토큰 비용 증가 | 각자 짧은 지침 유지 |
| 담당이 바뀌면 | 전체를 건드려야 함 | 해당 에이전트만 교체 |
| 누가 답했는지 | 알 수 없음 | 추적 가능 |

{: .important }
[Lab 2](./lab2.html)에서 지침 몇 줄 차이로 응답이 갈리는 걸 봤습니다. 지침이 200줄이 되면 그 몇 줄이 어디 묻혔는지 아무도 모릅니다. **쪼개는 이유는 성능이 아니라 통제 가능성입니다.**

### 자식 준비

1. [Lab 2](./lab2.html) 에이전트를 열고 **설명**(Description) 란에 아래를 입력합니다.

    ```
    한별소프트의 복리후생·휴가·근태·경조사 제도를 사내 규정 문서에 근거해 안내합니다. 복지포인트, 연차/반차, 경조휴가와 경조금, 식대 지급 기준에 대한 질문을 처리합니다. 개인의 잔여 연차나 포인트 잔액 같은 실시간 개인 데이터는 다루지 않습니다.
    ```

    ![촬영: 자식 에이전트 설명 입력](../assets/lab6/lab6-a01.png)

    {: .warning }
    이 문장을 대충 쓰면 부록 8번이 성립하지 않습니다. 정확히 붙여넣습니다.

2. 에이전트 이름이 `복리후생 안내 도우미 HGD`(본인 이니셜)인지 확인합니다. 부모 쪽에서 이 이름으로 찾습니다.

3. 우측 상단 **게시**를 눌러 이 에이전트를 게시합니다.

    ![촬영: 게시 완료](../assets/lab6/lab6-a02.png)

    {: .note }
    다른 에이전트가 나를 도구로 부르려면 내가 **게시된 상태**여야 합니다. 편집 중인 초안은 남이 부를 수 없습니다.

### 부모 만들기

4. 에이전트 목록에서 **새 에이전트**를 만들고 이름을 지정합니다.

    ```
    사내 종합 안내 HGD
    ```

    ![촬영: 부모 에이전트 생성](../assets/lab6/lab6-a03.png)

5. **지침** 란에 아래를 붙여넣고 저장합니다. 짧은 것이 핵심입니다.

    ```
    한별소프트 임직원의 사내 문의를 받는 1차 안내 창구입니다.

    - 직접 답하지 않습니다. 질문의 주제를 판단해 담당 에이전트에게 넘깁니다.
    - 담당 에이전트의 답을 받으면, 3줄 이내로 요약해 사용자에게 전달합니다.
      요약 끝에 어느 담당이 답했는지 한 줄로 표기합니다. 예: (담당: 복리후생 안내 도우미)
    - 담당 에이전트가 "모른다"고 답하면 지어내지 말고 그대로 전달합니다.
    - 담당이 없는 주제면 "담당 창구를 확인해 회신드리겠습니다"라고 안내합니다.
    ```

    ![촬영: 부모 지침 입력](../assets/lab6/lab6-a04.png)

6. 부모의 **도구 → 도구 추가**에서 **에이전트** 항목을 고르고, **본인 이니셜이 붙은** `복리후생 안내 도우미 HGD`를 추가합니다.

    ![촬영: 자식 에이전트를 도구로 추가](../assets/lab6/lab6-a05.png)

    {: .important }
    방금 한 조작이 [Lab 5](./lab5.html)에서 MSN 날씨를 붙인 것과 **화면상 거의 똑같습니다.** 부모 입장에서 자식 에이전트는 그냥 **도구 하나**입니다.

### 호출 확인

7. 부모의 테스트 창에 아래를 입력합니다.

    ```
    본인 결혼하면 휴가 며칠이고 경조금은 얼마예요?
    ```

    **완료 기준**: 3줄 이내 요약과 `(담당: 복리후생 안내 도우미)` 표기가 붙는다. 부모는 이 지식을 갖고 있지 않으므로, 답이 나왔다면 자식이 불려간 것입니다.

    ![촬영: 부모 응답 — 담당 표기](../assets/lab6/lab6-a06.png)

8. **[경로 끊기]** 자식으로 돌아가 1번의 설명을 아래처럼 뭉갠 뒤 저장하고 **다시 게시**합니다.

    ```
    사내 안내 도우미입니다.
    ```

    부모 테스트 창에서 7번과 **똑같은 질문**을 다시 던집니다. **완료 기준**: 자식이 불려가지 않거나 판단이 흔들린다.

    ![촬영: 설명을 뭉갠 뒤 라우팅 실패](../assets/lab6/lab6-a07.png)

    {: .important }
    **부모는 자식의 내부를 보지 않습니다.** 부모가 읽는 것은 **설명 한 문단**뿐이고, 그것만으로 넘길지 말지를 정합니다. [Lab 4](./lab4.html) 14번에서 오케스트레이터가 토픽 안을 보지 못했던 것과 같은 구조입니다.

9. **[경로 잇기]** 1번의 설명을 복원하고 다시 게시한 뒤, 같은 질문으로 재확인합니다.

10. 부모의 **계약 테스트 창**에서 이번 대화가 어느 도구를 거쳤는지 확인합니다.

    ![촬영: 자식 에이전트 호출 기록](../assets/lab6/lab6-a08.png)
